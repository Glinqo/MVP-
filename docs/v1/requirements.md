# 机电岗位培训AI - 网页系统需求文档 v1.0

## 文档说明

本文档基于 `Glinqo/MVP-` 仓库当前 main 分支 (commit 58cf0b7) 的代码基线编写。定义从当前 Python MVP 迁移到 Spring Boot + Vue 3 全栈网页系统的第一版需求范围。

## 1. 当前系统概述

当前仓库是一个面向机电一体化职业新人培训的轻量智能体 MVP，核心功能包括：

| 功能模块 | 当前实现 | 技术栈 |
|---------|---------|--------|
| AI 问答对话 | 规则引擎 + 可选 LLM 兜底 | Python http.server |
| 岗位能力图谱 | 25 个能力节点，D3.js 力导向图 | JSON + 前端 D3.js |
| 排故角色扮演 | 4 个诊断场景，多步骤交互 | Python scenario.py |
| 自测系统 | 20 道确定性评分诊断题 | Python quiz.py + scoring.py |
| 知识检索 | 50+ 条知识条目，向量搜索 | FAISS + SQLite |
| 学生画像 | 能力状态追踪、过程指标 | SQLite + JSON |
| 证据驱动更新 | 爬虫→证据→提案→教师确认→快照 | SQLite evidence.db |
| 对话记忆 | 会话摘要、增量图谱更新 | SQLite sessions.db |
| SSE 流式 | 知识问答流式输出 | Python generator + SSE |

## 2. 目标架构

```
浏览器 (Vue 3)
  |
  v
RuoYi Spring Boot 后端 (Java)
  |-- 用户/权限/菜单 (RuoYi 复用)
  |-- 会话管理 (新增)
  |-- 聊天 API (新增，代理到 Python)
  |-- 文件/知识库 (新增)
  |-- 日志/统计 (RuoYi 复用 + 扩展)
  |
  v
Python 智能体服务 (FastAPI)
  |-- 意图识别 & 对话策略
  |-- 知识检索 (FAISS)
  |-- 图谱构建 & 更新引擎
  |-- 排故场景 & 评分
  |-- 学生画像 & 学习证据
```

**铁律**：前端不直接访问 Python 服务。所有请求经过 Spring Boot 后端。

## 4. 非功能需求

| 需求 | 目标 |
|------|------|
| 可维护性 | 前后端分离，模块化设计 |
| 模块化 | 聊天/图谱/场景/配置独立模块 |
| 可扩展性 | 多智能体支持（数据库层面）、插件式工具 |
| 权限隔离 | 学生/教师/管理员三级权限 |
| 错误可观测性 | 结构化日志，调用链路可追溯 |
| 接口超时 | Spring Boot → Python 30s 超时 |
| 日志规范 | 统一格式，含 traceId |
| 数据库索引 | 会话ID、用户ID、时间戳索引 |
| 并发访问 | 支持同时多用户聊天 |
| 文件大小限制 | 上传文件 ≤ 10MB |
| 模型调用频率限制 | 每用户每分钟 ≤ 10 次 |
| 浏览器兼容 | Chrome / Edge / Firefox 最新版 |
| 响应式布局 | 桌面优先，平板可适配 |
| 测试要求 | 核心 API 80% 覆盖率 |

## 5. 不在第一版范围

- 实时 SSE 流式聊天（第二版）
- 多智能体切换（第二版）
- 文件上传和知识库全文检索（第二版）
- Docker Compose 部署（第二版）
- Nginx 反向代理（第二版）
- 自动化 CI/CD（第二版）
- 移动端适配（后续）
- AI 监控仪表盘（后续）
- P0 爬虫管线（独立维护，不纳入网页系统）

## 6. 关键风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Python 智能体迁移到 FastAPI 工作量 | 高 | 最小化改动，封装现有函数 |
| RuoYi 框架学习成本 | 中 | 优先复用，仅新增业务模块 |
| 前后端数据模型不一致 | 中 | 严格按 API 契约开发 |
| 规则引擎依赖 JSON 文件 | 中 | 保留 JSON，FastAPI 读文件不改格式 |
